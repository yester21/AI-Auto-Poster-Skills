# H 태그 규칙

서버(`AIAP_Writing_Guide::headings()`)와 동일한 값이다.

## 핵심 — H1 을 쓰지 않는다

**테마가 글 제목을 H1 으로 출력한다.** 본문에 H1 을 넣으면 한 문서에 H1 이 둘이 되어
문서 구조가 무너진다. 서버 게이트가 `no_h1` 로 거부한다.

```
❌ <h1>홈트레이닝 시작하기</h1>     ← 제목과 중복
✅ <h2>홈트레이닝을 시작하기 전에</h2>
```

## 허용 태그

| 태그 | 위치 |
|---|---|
| `h2` | 본문 섹션의 유일한 최상위 |
| `h3` | 반드시 H2 하위 |
| `h4` | H3 하위 (드물게) |

## 규칙

| 항목 | 값 |
|---|---|
| H2 개수 | 3 ~ 12 |
| 키워드 포함 H2 | **최소 1개** |
| H2 길이 | 30자 이내 |
| H2 끝 마침표 | 쓰지 않음 |
| 순서 | 검색 의도 순 |

## 순서 — 검색 의도

독자가 검색해서 들어온 순간 궁금해하는 순서로 배치한다.

```
정보 (무엇인가)
  → 방법 (어떻게 하는가)
  → 비교 (무엇이 나은가)
  → 주의 (무엇을 조심하는가)
  → 결론
```

## 좋은 H2 / 나쁜 H2

```
❌ 소개              ← 키워드 없음, 정보량 없음
❌ 다양한 측면       ← 상투적, 내용 예고 불가
❌ 결론              ← 너무 일반적

✅ 홈트레이닝을 시작하기 전에 정할 세 가지
✅ 초보자를 위한 삼 주 루틴
✅ 운동 효과를 지키는 식사
```

**H2 는 그 섹션이 무엇을 답하는지 한눈에 알 수 있어야 한다.** 검색 결과의
사이트링크로 노출될 수 있으므로 그 자체로 읽혀야 한다.

## H3 사용

- H2 안의 세부 구분에만 쓴다
- H2 없이 H3 를 쓰지 않는다
- H3 를 남발하면 목차가 산만해진다. H2 하나당 0~3개 정도가 적당하다

## 서버 검사

`aiap/check-content-quality` 응답에서 확인한다.

```json
{
  "metrics": { "h1": 0, "h2": 3, "h2_with_kw": 2 },
  "checks": { "no_h1": true, "h2_min": true, "h2_keyword": true }
}
```
